# ADR 0003: Almacenamiento de Metadatos Locales de LIT dentro del Directorio de Git

## Contexto
LIT necesita almacenar metadatos propios del sistema que no forman parte directa del historial de versiones de Git ni de los archivos fuente del proyecto. Ejemplos de estos datos son:
- El registro de auditoría local de las últimas 10 acciones del desarrollador para dar soporte al comando `lit undo`.
- Configuraciones y preferencias específicas del motor LIT en el entorno del desarrollador.

## Problema
Si guardamos estos metadatos en directorios raíz nuevos (como una carpeta `.lit/`), corremos el riesgo de ensuciar el Workspace del desarrollador. Además:
- El usuario podría borrar la carpeta por error al limpiar directorios.
- Obliga a configurar filtros de exclusión (`.gitignore`) para evitar subir estos metadatos privados al repositorio remoto de Git, lo cual añade complejidad y contradice la filosofía de simplicidad.

## Alternativas
1. **Crear una carpeta `.lit/` en la raíz del Workspace**:
   - *Pros*: Fácilmente accesible para el motor y visible para depuración.
   - *Contras*: Ensucia la raíz del proyecto, requiere exclusiones explícitas y es susceptible de borrados accidentales.
2. **Almacenar metadatos en un archivo global del sistema del usuario**:
   - *Pros*: Workspace totalmente limpio.
   - *Contras*: Dificulta mover el repositorio de ruta o de disco sin perder el historial de `undo` local del proyecto.
3. **Uso de la carpeta oculta `.git/lit/`**:
   - *Pros*: Git ya oculta la carpeta `.git/` de los editores y herramientas. Todo el contenido dentro de `.git/` está implícitamente fuera del control de versiones y del Workspace, eliminando la necesidad de archivos de exclusión. Ofrece aislamiento total del Workspace y los metadatos viajan de forma segura si el usuario mueve la carpeta del proyecto.
   - *Contras*: Requiere permisos de escritura dentro de la carpeta de metadatos de Git (lo cual es estándar para cualquier herramienta del ecosistema).

## Decisión
Se elige la **Alternativa 3: Almacenar metadatos en `.git/lit/`**.
El motor de LIT creará y gestionará de forma transparente un subdirectorio llamado `lit` dentro del directorio de infraestructura de Git. El historial de auditoría de `undo` se guardará como un archivo JSON local en `.git/lit/audit_log.json`.

## Consecuencias
- Cero archivos o directorios adicionales en la raíz del Workspace del desarrollador (diseño limpio).
- Los metadatos de LIT nunca se comitearán por error ni requerirán reglas de ignorado extra.
- El ciclo de vida de los metadatos de LIT está fuertemente acoplado al del repositorio Git (si se borra `.git`, se limpian también los logs de LIT, lo cual es predecible).
